# Last Lantern v1.0 — публикация на GitHub Pages

Подготовлено 28.09.2026. Ничего не опубликовано; репозиторий и коммит не создавались. Следующие действия выполняются только после отдельного подтверждения владельца.

## Состав и ограничения

В папке — проверенные файлы Release Candidate без изменения игрового кода и аудио; добавлены .nojekyll, .gitattributes и эта инструкция. index.html находится в корне. Копировать нужно содержимое папки, не ZIP и не внешнюю папку целиком. SHA-256 исходных 12 файлов сохранены. CC0-источники описаны в AUDIO_SOURCES.md, хеши пяти записей — assets/audio/manifest.json. Встроенный audio-data.js не требует загрузки удалённых оригиналов.

Аудиопакет: 36 116 965 байт (34,44 МиБ). Он превышает ограничение веб-загрузки GitHub 25 МиБ, но меньше предела обычного Git 100 МиБ. Не используйте Upload files для всего проекта, Git LFS или размещение ZIP вместо файлов сайта. Общий объём существенно меньше лимита опубликованного Pages-сайта 1 ГБ.

На медленном соединении после 12 секунд загрузки пакета включается прежний резервный синтезатор. Это известное ограничение принятой сборки, не ошибка GitHub Pages. Перед публикацией подтвердите, что такой режим допустим. Звук включается только после действия пользователя. Основные целевые устройства — настольные компьютеры и ноутбуки с клавиатурой.

## Публикация после подтверждения

1. Войдите в github.com своим аккаунтом. Уточните владельца и имя репозитория (например last-lantern). Создайте пустой репозиторий только после одобрения публикации. Для бесплатного GitHub Pages обычно используется публичный репозиторий; не создавайте README/.gitignore/license на сервере, чтобы избежать расхождения начальной истории. Не назначайте лицензию всему авторскому коду без решения владельца: CC0 здесь относится к сторонним аудиозаписям.
2. Откройте PowerShell в папке Last-Lantern-v1.0-Publish. Команды ниже — инструкция, они ещё не выполнялись. Подставьте фактический OWNER и REPOSITORY в URL.

```powershell
# Откройте PowerShell в корне этой сборки.
$gitExe = 'git'
& $gitExe init -b main
# Если Git попросит автора — задайте имя и подходящий GitHub noreply email
# локально для этого репозитория через git config user.name / user.email.
& $gitExe add .
& $gitExe status --short
& $gitExe commit -m 'Release Last Lantern v1.0'
& $gitExe remote add origin 'https://github.com/OWNER/REPOSITORY.git'
& $gitExe push -u origin main
```

3. При необходимости пройдите штатную авторизацию Git. Не помещайте токен в URL, исходники или эту инструкцию. Если установленный Git не предлагает работающий способ входа, остановитесь и настройте авторизацию отдельно; копирование через веб-форму не решит ограничение размера аудиопакета.
4. В GitHub откройте Settings → Pages → Build and deployment. Source: Deploy from a branch. Branch: main, папка / (root). Сохраните. .nojekyll уже подготовлен для статических файлов.
5. Дождитесь успешного развёртывания Pages и откройте URL, показанный GitHub. Для project site он обычно имеет вид https://OWNER.github.io/REPOSITORY/ . Наличие подкаталога поддерживается относительными путями; не меняйте их на начинающиеся с /.
6. Проверьте Network/Console: index.html, style.css, audio-bootstrap.js и audio-data.js должны загружаться без 404; до готовности виден статус. После Start проверьте музыку, переход после третьего фонаря, паузу, повторный старт, обе сложности и победу. При 1024×768, 1280×720 и 1366×768 viewport элементы должны быть доступны без прокрутки при масштабе 100%.
7. Повторите холодную загрузку с Disable cache и точными Fast/Slow 3G в Chrome/Edge. На медленной сети ожидается предупреждение о резерве. После снятия ограничения и обновления должны загрузиться записи CC0. Послушайте звук через обычные динамики. Автоматические проверки не подтверждают субъективное качество.

## Если публикация отложена

Храните папку и ZIP локально. Для загрузки позже используйте тот же установленный Git; перед push ещё раз подтвердите владельца, имя, публичность и право публиковать весь проект. Наличие ZIP не означает публикацию, и GitHub Pages не распаковывает ZIP в сайт. Резервную копию v4 не использовать как каталог публикации и не изменять.
